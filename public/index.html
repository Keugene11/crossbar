What is this?

Without a router: every AI provider has its own API. Using Claude and GPT means writing the integration twice, holding two sets of credentials, and going down whenever whichever one you picked goes down.

crossbar sits in front of them

You send it one kind of request. It works out which provider should handle it, rewrites the request into that provider's own format, and sends the answer back in the shape you already expect.

One account instead of many

The provider credentials sit on the gateway, not in your app. Whoever runs a crossbar holds them once and issues keys with credit on them — so using it means a single key and a single balance, not an account with every AI company.

If a provider fails, it tries the next

Rate limited, erroring, or slow — crossbar moves on to another endpoint mid-request, and your app just sees a normal reply. It picks the cheapest capable option by default, and records what every request cost and which providers it tried.

Do I need my own keys?

Depends which side of the gateway you are on.

Using someone's crossbar? No.

You get a key with credit on it and call any model in the catalog. You never need an Anthropic or OpenAI account — that relationship belongs to whoever runs the gateway. One key, one balance, every model. That is the whole point of a router.

Running crossbar? Yes, once.

You hold the provider credentials, and hand out keys to everyone else:

curl -X POST $HOST/v1/keys   -H "Authorization: Bearer $OPERATOR_KEY"   -d '{"label":"my app","credit":5}'

# -> { "key": "sk-crossbar-...", "limit": 5 }
#    shown once; only its hash is stored

Every generation debits what it actually cost. A key that runs out gets 402; a request that failed is never charged. An issued key cannot manage keys, so it cannot mint itself more credit.

The three kinds of key

issued keys Tenant keys. Created with POST /v1/keys, carry a credit balance. This is what you hand to an app or a teammate. CROSSBAR_API_KEYS Operator keys. From configuration, unlimited, unmetered. These can issue and revoke tenant keys. ANTHROPIC_API_KEY Provider keys. Let crossbar reach Claude and GPT. Set once by the operator, never seen by anyone using the gateway.

What about this hosted demo?

It has no provider keys configured, so crossbar/echo works and real models come back 401 from the provider. That failure is honest: routing and translation ran, the credentials simply weren't there.

Quickstart

Three steps. The first one works right now, with no account anywhere.

Call the demo model

Every gateway needs credentials before you can try it. crossbar/echo is a built-in model that answers without calling any upstream, so the whole path — routing, streaming, usage accounting — works before you have an account with anyone. It is free and cannot spend money.

curl https://crossbar-eta.vercel.app/v1/chat/completions   -H "Authorization: Bearer DEMO_KEY"   -H 'content-type: application/json'   -d '{"model":"crossbar/echo","messages":[{"role":"user","content":"hello"}]}'

Point an existing client at it

crossbar speaks the OpenAI Chat Completions API, so any OpenAI client works — change the base URL and the key, nothing else.


        

      


      

        

          
Add provider keys to reach real models

          
To route to anthropic/claude-opus-5 or openai/gpt-5, the gateway
             needs credentials for those providers. Run it yourself and they stay on your machine:

          
git clone https://github.com/Keugene11/crossbar && cd crossbar
pnpm install

# your provider keys, never crossbar's
echo "ANTHROPIC_API_KEY=sk-ant-..." >> apps/gateway/.env
echo "CROSSBAR_API_KEYS=sk-my-own-key" >> apps/gateway/.env

pnpm dev   # http://localhost:8080

          
The hosted demo above has no provider keys configured, so real models there
             return 401 from the provider — you will see the routing worked and the
             credentials were missing, which is the honest failure.

API
OpenAI-compatible. Point an existing client at this host and change nothing else.

    
curl https://crossbar-eta.vercel.app/v1/chat/completions \
  -H "Authorization: Bearer $CROSSBAR_KEY" \
  -H 'content-type: application/json' \
  -d '{
    "model": "anthropic/claude-opus-5",
    "models": ["openai/gpt-5"],
    "provider": { "sort": "price", "data_collection": "deny" },
    "messages": [{ "role": "user", "content": "hello" }]
  }'
